# TMflow 舊流程改成雙張拍照版：完整施工順序

> 歷史遷移文件（2026-10-05 標示）：雙張方案已被單張基準取代。本文舊節點對照不保證與目前 v3.1 模型一致，不可據此刪除現場節點。

更新：2026-09-20。本表是**改版施工說明**，不是已套用到控制器的紀錄。新版節點 ID 以 [v3 節點設計](tmflow_v3_nodes.json) 為準；舊節點 ID 僅用來定位舊文件中的功能。尚未取得目前 TMflow 專案匯出，因此若現場編號不同，**以節點實際功能辨識，不按同號刪除**。例如舊 B3 是 heartbeat，新 B3 是 BUSY。

已由使用者確認：IP、指令通訊、Listen 可用；DO3 是吸盤控制。尚未確認：DO3 極性、真空檢知、拍攝硬體配置與機械安全高度。以下暫以同一相機由手臂移至 A/B 兩個視角設計。新 Python 雙圖配對和動態 Point 下發**尚未整合完成**。

## 施工前

1. 在 TMflow 另存可回退的舊專案，以下只改工作副本。不要執行改到一半的新舊混合流程。
2. 保留現有已通的 Network/Listen 裝置、IP、Port、認證及連線方式；在原 Listen Pass 後接新版接令段。舊程式有外部 heartbeat 使用者時，先確認相依，再決定是否移除。
3. 先建立固定點與動態 Point 模板（下文「點位與資料」）。**未完成教點、動態座標下發及低速空載驗證，不執行自動動作。**

## 一、啟動與接令：替換舊 Listen 後的檢查段

| 順序 | 新節點 | 舊版節點去向及設定 | 下一站 |
| --- | --- | --- | --- |
| 1 | A1 Start | 保留舊啟動入口；只允許空載且姿態已知時啟動。 | A2 |
| 2 | A2 Set | 替代舊初始化；清命令暫存，不清除仍須防重送的已完成紀錄。 | A3 |
| 3 | A3 Set/IO | 原啟動釋放輸出改為 **DO3 OFF**，但只在確認空載時執行。 | A4 |
| 4 | A4 Point | 原回安全點改指 `P_READY_SAFE`。 | A5 |
| 5 | A5 Network | 原 READY 回報沿用網路通道；`robot_state=1` 表示 ready。 | L1 |
| 6 | L1 Listen | 保留已通的 Listen；Pass 後接新 B1，不能讓舊命令直接進動作。 | B1 |
| 7 | B1 Set | **替代舊 B6-B8 檢查段**：分類為 `0` 拒絕、`1` 有效新命令、`2` 同內容已完成命令重送。檢查命令 ID/內容、棋盤範圍、來源不等於目標、kind/action；同 ID 不同內容必須拒絕。 | B1A |
| 8 | B1A If | 新增在 B1 後：`cmd_class==1` 才准執行。 | Yes B2；No B1B |
| 9 | B1B If | 新增在 B1A.No 後：`cmd_class==2` 回傳快取，不再動手臂。 | Yes R1；No E1 |
| 10 | B2 Set | 替代舊 B2 狀態寫入：保存本次命令 ID、內容摘要及 capture ID；`robot_state=2` 表示 busy。 | B3 |
| 11 | B3 Network | 替代舊 B5 BUSY 回報；帶相同命令 ID。舊 B3 heartbeat **不是**此節點。 | B4 |
| 12 | B4 If | 新增在 BUSY 後：`kind=1` 掃描；`kind=2` 移子。其他 kind 已在 B1 拒絕。 | 掃描 S1；移子 B5 |
| 13 | B5 If | 替代舊 B10「是否吃子」判斷：`action=1` 走 C1；`action=0` 走 M1。 | 吃子 C1；一般 M1 |
| 14 | R1 Network | 新增在 B1B.Yes：重送同 ID 的已完成結果，**不重新拍照或移動**。 | E2 |
| 15 | E1 Network | 新增在 B1B.No：回拒絕原因與命令 ID；不進 BUSY。 | E2 |
| 16 | E2 Set | 新增在 R1/E1 後：只清本次 `cmd_ready`，保留完成快取。 | L1 |

舊 B9 固定座標/假資料設定，在 Python 對新 Point 模板下發成功後退出主線。舊 B1/B3 heartbeat 若有外部監控相依，保留成**不阻塞命令路徑**的獨立機制；無相依且驗證後才刪。舊 B6-B8 檢查段在 B1/B1A/B1B 完成後刪，不要兩套檢查串接。

## 二、吃子分支：替換舊吃子及死棋放置段

只有 `kind=2, action=1` 才走本段；吃完被吃棋，再進共用移子段 M1。

| 順序 | 新節點 | 舊版節點去向及設定 | 下一站 |
| --- | --- | --- | --- |
| 17 | C1 Point | 舊目的格上方動作改指 `P_DST_ABOVE`，使用 Python 下發的目的格 XY/安全 Z。 | C2 |
| 18 | C2 Point | 舊目的格下探改指 `P_DST_PICK`；只能按已驗證路徑垂直下探。 | C3 |
| 19 | C3 Set/IO | 保留原吸取 IO 的**功能**，實際輸出改 DO3 ON。不可在此直接把 `has_piece=true` 當作吸附已證實。 | C4 |
| 20 | C4 Wait for | 保留/新增吸附穩定等待；若有真空檢知，改以檢知結果判斷。 | C5 |
| 21 | C5 Point | 保留抬升功能，回 `P_DST_ABOVE`。 | C6 |
| 22 | C6 Point | **替代舊 C3 設 cap_x/cap_y/drop_z + 直接斜走的入口**：先到固定 `P_DROP_ABOVE`。 | C7 |
| 23 | C7 Point | **替代舊 C4 直接 PTP 到落點**：再沿已驗證垂直路徑到 `P_DROP_RELEASE`。 | C8 |
| 24 | C8 Set/IO | 原死棋區釋放 IO 改 DO3 OFF。 | C9 |
| 25 | C9 Wait for | 保留/新增釋放穩定等待；不可僅用輸出命令推定棋子已離開。 | C10 |
| 26 | C10 Point | **新增在舊釋放等待後**：先升回 `P_DROP_ABOVE`，再橫移。 | M1 |

舊 `dead_slot_index`、多個死棋格與固定 `cap_x/cap_y/drop_z`，若新版確定只用一個收棋容器且無其他引用，在新 C6/C7 驗證後移除。若仍須分類存放死棋，這一段不能直接套用單一落點，須保留/重設多落點策略。

## 三、共用移子：替換舊來源/目的地動作

舊 B11/B12（來源）及 B13/B14（目的地），或舊文件中功能相同的節點，改成下列**同一段**，不得讓吃子分支另有一套移子座標。`kind=2, action=0` 直接由 B5 到 M1；`action=1` 由 C10 到 M1。

| 順序 | 新節點 | 舊版節點去向及設定 | 下一站 |
| --- | --- | --- | --- |
| 27 | M1 Point | 原來源格移動改 `P_SRC_ABOVE`。 | M2 |
| 28 | M2 Point | **新增**來源格垂直下探 `P_SRC_PICK`。 | M3 |
| 29 | M3 Set/IO | 原來源吸盤 IO 改 DO3 ON；移除「ON 即 `has_piece=true`」的假確認。 | M4 |
| 30 | M4 Wait for | 保留/新增吸附等待；真空檢知未裝時僅是時間等待。 | M5 |
| 31 | M5 Point | **新增**回 `P_SRC_ABOVE`。 | M6 |
| 32 | M6 Point | 原目的格移動改 `P_DST_ABOVE`；確認橫向通道淨空。 | M7 |
| 33 | M7 Point | **新增**目的格垂直放置 `P_DST_PLACE`。 | M8 |
| 34 | M8 Set/IO | 原放棋 IO 改 DO3 OFF。 | M9 |
| 35 | M9 Wait for | 保留/新增釋放等待。 | M10 |
| 36 | M10 Point | **新增**回 `P_DST_ABOVE`。 | M11 |
| 37 | M11 Point | 替代舊 F1「回 P_READY_SAFE」的功能；回安全待機點。 | S1 |

所有 `Point` 是目標模板，不是「直接硬編每一格」；要先確認本次 Point.Value 寫入成功、Base/TCP 一致，再允許 B3 發 BUSY 並動作。不能把尚未寫入的舊座標當有效值。

## 四、雙張拍照：替換舊單張 Vision 段

整段放在 **M11 後**；純掃描由 B4 直接進 S1。移子完成後只執行**同一段 S1-S12**，不要再接舊版額外的全盤重掃。A/B 是同一次 `capture_id` 的兩張影像；A 上傳收到 ACK 才去 B，B 上傳收到 ACK 才能進 DONE。

| 順序 | 新節點 | 舊版節點去向及設定 | 下一站 |
| --- | --- | --- | --- |
| 38 | S1 Point | **新增** A 位接近點 `P_PHOTO_A_APPROACH`。 | S2 |
| 39 | S2 Point | 舊單張拍照點可教成 A 位 `P_PHOTO_A`。 | S3 |
| 40 | S3 Wait for | 保留/新增 A 位停穩等待。 | S4 |
| 41 | S4 Vision | 舊單張 Vision **替代為 A 圖**：`JOB_BOARD_A`，攜命令 ID、capture ID、view=A，上傳並等 A ACK。 | S5 |
| 42 | S5 Point | **新增** A 位退回接近點。 | S6 |
| 43 | S6 Point | **新增**先回 `P_READY_SAFE`，再往 B 位；中途路徑須實機確認。 | S7 |
| 44 | S7 Point | **新增** B 位接近點 `P_PHOTO_B_APPROACH`。 | S8 |
| 45 | S8 Point | **新增** B 位拍照點 `P_PHOTO_B`。 | S9 |
| 46 | S9 Wait for | **新增** B 位停穩等待。 | S10 |
| 47 | S10 Vision | **新增** `JOB_BOARD_B`，同一 capture ID、view=B，上傳並等 B ACK。 | S11 |
| 48 | S11 Point | **新增** B 位退回接近點。 | S12 |
| 49 | S12 Point | **新增**回 `P_READY_SAFE`。 | F1 |

Python 必須按 `capture_id + view` 配對、去重、設逾時；不同批次不能拼成一盤。既有程式目前不應被視為已支援雙圖，這項接線/程式整合要在實機測前完成。

## 五、完成與故障：替換舊 F/G 尾段

| 順序 | 新節點 | 舊版節點去向及設定 | 下一站 |
| --- | --- | --- | --- |
| 50 | F1 Set | 替代舊 F2 完成狀態寫入：先快取本次結果、命令 ID、capture ID、`robot_state=1`。 | F2 |
| 51 | F2 Network | 替代舊 F3 DONE：帶同一命令 ID/capture ID；只在 B 圖 ACK 後送出。 | F3 |
| 52 | F3 Set | 替代舊 F5 清理：只清本次 `cmd_ready`，保留完成結果供重送。 | L1 |
| 53 | G1 Set | 替代舊 G 錯誤狀態：記錄故障、命令 ID、目前步驟及吸盤狀態；不可覆寫已完成快取。 | G2 |
| 54 | G2 Network | 替代舊 G2 ERROR：有限次回報；通訊故障不能無限阻塞。 | G3 |
| 55 | G3 Stop | 替代舊 G 強制 DO OFF/自動回原點：停在可診斷狀態，交人工確認姿態/持棋/輸出後復歸。 | 停止 |

舊 F4 固定 100 ms 若被拿來當「電腦收到 DONE」證據，**直接刪除這個假 ACK**；實際收訊須用通訊協定確認。若它是經量測需要的機械停穩時間，改留在對應 S3/S9 或吸放等待處。故障出口不是「任何錯誤都 DO3 OFF/回原點」；停機時控制器實際 DO3 保持/復位行為仍需查設定並實測，不能只靠流程圖保證不掉棋。

## 六、最後退出/刪除舊主線節點

完成上述替代段後，對**工作副本**逐項確認連線，再刪，不是在實機原專案照 ID 全選：

| 舊版內容 | 處置 |
| --- | --- |
| 舊 B6-B8 純 range/action 檢查、舊 B9 假命令/固定座標、舊 B10 分流 | 新 B1/B1A/B1B、Python 動態座標、新 B4/B5 驗證後，從主線移除舊段。 |
| 舊 B11-B14 與重複的來源/目的地移動段 | 新 M1-M11 空載與單步驗證後移除；原有可用動作參數應先搬到新節點。 |
| 舊 C3 cap 座標 Set + C4 斜向 PTP | 新 C6/C7/C10 驗證後刪除舊斜向落子段。 |
| 舊單張 Vision、舊的第二次全盤重掃 | 以新 S4/S10 和一次 S1-S12 替代；不要同時保留兩條拍照主線。 |
| 舊 F1-F5 中已被 M11/F1-F3 取代的節點 | 核對功能逐一退出；舊 F4 假 ACK 直接移除。 |
| 舊 G 強制 DO OFF 與自動回原點 | 從故障路徑移除，改接 G1-G3；正常釋放 DO3 節點必須保留。 |
| `has_piece=true` 緊接 DO3 ON 的 Set | 移除假感測賦值；真空感測器若存在，另以其訊號判斷。 |
| 舊 heartbeat、`dead_slot_index`/多死棋位 | 先查外部監控及其他節點引用，無相依才移除。 |

## 七、點位與 Python 必備資料

**TMflow 固定教點 7 個：** `P_READY_SAFE`、`P_PHOTO_A_APPROACH`、`P_PHOTO_A`、`P_PHOTO_B_APPROACH`、`P_PHOTO_B`、`P_DROP_ABOVE`、`P_DROP_RELEASE`。

**Python 每次命令寫入的動態 Point 模板 5 個：** `P_SRC_ABOVE`、`P_SRC_PICK`、`P_DST_ABOVE`、`P_DST_PICK`、`P_DST_PLACE`。這些模板在 TMflow 先建立，實際位姿由 Python 按棋盤格計算後送入，不要在 TMflow 固定寫死某一格。

**Python 校正資料：** 棋盤角/格點對應（現有 a0、i0、a9 加 i9/e4 holdout 的策略須重驗）、安全/吸取/放置 Z、工具姿態 Rx/Ry/Rz、共同 Base/TCP、A/B 各自像素到棋盤的校正、影像重疊區的去重規則，以及命令 ID/capture ID。**只填棋盤大小與兩個拍照點不夠**；照片像素到格點、格點到機械座標必須分別校正。

**執行前關卡：** Python 的 Listen/Point.Value 寫入、雙圖上傳 ACK/配對、DONE/重送契約都要與 TMflow 實際版本互通。先做無動作通訊測試，再做空載低速點位/路徑測試，最後才測吸棋；夾持、碰撞與急停由現場安全程序把關。本文件只完成流程設計與舊版遷移對照，**不代表控制器或 Python 已改好或實機已驗證**。

完整節點欄位與分支規格見 [v3 全節點設計](TMFLOW_1_82_51_FULL_NODE_DESIGN.md)；本表的 55 個新節點與 [機器可讀設計](tmflow_v3_nodes.json) 一致。
