三、系統目的與架構
目的：讓人透過實體象棋盤與機械手臂對弈；文件設定的研究情境包含高齡陪伴及可用性評估。此目的不代表已驗證醫療或心理效益。
輸入：玩家網頁操作、相機影格、機械手臂回報、棋盤及工具校正。
介面：Flask REST、Socket.IO、TMvision HTTP ingest、影像串流。
應用：bootstrap 統一組裝；WorkflowCoordinator 包含玩家完成、辨識、AI及機械動作相關邏輯。既有複驗程式不作為現行流程。
狀態：EventBus 傳遞事件，StateManager/reducers 更新狀態；服務由 container 共用；SQLite 保存事件及相關資料。
視覺：VisionSystem 預設主路徑；OpenCV/TMvision → FrameBuffer → detector/YOLO（可用 SAHI fallback）→ 校正/棋格/FEN。
引擎：Pikafish + NNUE，服務處理分析與引擎生命週期。
手臂：RobotFacade → RobotService → tmflow_json、techmanpy 或 modbus；假機器人另依設定選用。
輸出設計包含棋局/狀態畫面、實體移子、紀錄及匯出；手臂流程尚未完成。
設定：.env、可選 backend/config.yaml、啟用時的 data/setup_settings.json；APP_ENV 與 SYSTEM_MODE 用途不同。
依賴宣告包含 Flask、Flask-SocketIO、techmanpy==1.2、pyModbusTCP、OpenCV、Ultralytics、SAHI、ONNX 等。宣告版本不等於所有套件已安裝或全部相容。

四、程式與文件的關鍵界線
1. RobotService 已支援 techmanpy，故「完全沒有 Listen adapter」不精確。techmanpy_adapter.py 透過 connect_sct 直接送 PTP/Line、QueueTag 與吸盤 script；它不等於新設計的動態 Point 寫入後 ScriptExit 交回 TMflow 節點。
2. tmflow_json_adapter.py 使用自訂 JSON line；名稱含 TMflow 不代表它能直接對 Listen 5890 傳 JSON。
3. FrameBuffer.get_latest_raw 會清掉較舊影格。這適合即時串流，不足以保存同批 A/B、capture_id 與校正版本。
4. WorkflowCoordinator 的完成回報路徑會開啟影像複驗 session；尚不能據此證明已能以同筆 DONE+A+B 驅動雙圖複驗。
5. Kinematics 既有棋格 XY 映射與視覺到機械平面校正；不能推論自動處理棋盤傾斜的 Z、工具長度、姿態及路徑避障。
6. 盤點時 JSON 節點模型為 v3.1 單張、23 節點、DESIGN_ONLY；保留的指南/設計書仍是 v3.0 雙張、55 節點。--check 已確認 Generated guide is stale。此為資料一致性問題，未擅自決定採用哪套硬體流程。
7. 既有文件記錄 IP/Listen 可用、DO3 控制吸盤；本次沒有控制器連線或現場量測，不將它升格為新實測。

六、已核對的 1.82 工程知識
以下頁碼皆指上述本機 1.82 原廠手冊，不混用 2.x：
A. 點位（p.236）：Point[名稱].Value 是可讀寫 6 元素 float 陣列 XYZ/RX/RY/RZ；Pose 是 3 元素構型。BaseName/TCPName 在 Point 物件為唯讀。只改 Value 不等於變更 Base/TCP，也不自動證明構型或路徑可達。
B. Listen（p.248）：TCP server 隨專案啟動建立、停止關閉；文件指定 port 5890。TCP 連通不代表流程已進 Listen。Connection Timeout/Data Timeout 單位毫秒，<=0 不逾時；是否使用無限等待需依專案失敗處理決定。
C. 封包（pp.250–253）：格式為 $Header,Length,Data,*Checksum 加 CRLF。Length 是 UTF-8 bytes；Checksum 對 $ 與 * 之間 bytes 做 XOR，不包含兩個邊界字元。TMSCT 用於 script；Script ID 為英數字，用來關聯回覆。自訂業務 cmd_id 與 Script ID 應分清。
D. 狀態（pp.254–258）：TMSTA 00 查外部 script 模式；01 查 QueueTag；90–99 可用於資料訊息。TMSTA 不要求已進 Listen。CPERR 是通訊錯誤，與 TMSCT 的語法 ERROR 不同。
E. 完成語意（pp.248、264–265）：運動及 DO/AO 有排程順序；不能把 TCP write 成功或收到語法 OK 當整個實體棋步已成功。需確認 QueueTag／應用完成訊息，再用影像確認棋局。
F. ScriptExit（p.249、260）：無參數版本等待已排程指令完成，再離開 Listen 走 Pass；其後同份 script 不執行。ScriptExit(0)／(1) 是優先命令，立即停止運動並清除運動緩衝，分別走 Fail／Pass。不能互換，也不是硬體急停。
G. 變數（p.253）：Listen 可讀寫既有專案變數；在 Listen 宣告的是當次區域變數，不會替專案建立持久變數。需預先建立交握欄位。
H. 外部連線（第6章，pp.218–234）：socket_read/socket_read_string/socket_send/socket_sendline 使用已設定的連線；應依1.82連線設定及函式簽章實作，不猜測存在 socket_open 類 API。
I. 運動與視覺（第9章）：PTP、Line、ChangeBase、ChangeTCP、QueueTag、Vision_DoJob 及其移動版本須分清執行時序。Vision job 執行不等於 Python 已收到新影像；取像、傳輸 ACK、辨識結果、實體動作 DONE 是不同階段。
J. I/O：DO3 接線端、極性、負壓回授與停止時行為由現場確認。輸出設值成功不能證明吸住棋子。
K. 棋盤校正（專案設計推導）：90 交點為9列檔×10橫列，兩方向分別8、9個間距；至少獨立保留驗證點。A/B設計需兩視角各自校正及重疊衝突處理；單張設計則需確定整盤解析度與遮擋符合辨識需求。
